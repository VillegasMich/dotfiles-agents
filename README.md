# dotfiles-agents

My AI coding-agent setup (skills, Claude Code settings and plugins, Codex config) that I can
sync to any machine. It complements [`dotfiles-macos`](https://github.com/VillegasMich/dotfiles-macos):
that repo holds macOS-only config, while everything here works the same on macOS and Linux.

The repo mostly stores **manifests, not copies**. Skills are recorded as `name + source`
and reinstalled from upstream, so every machine gets current versions and the repo stays small.
Only files I wrote myself (status line script, Codex rules, my own skills) live here and are
symlinked into place.

## Quick start

```sh
git clone git@github.com:VillegasMich/dotfiles-agents.git ~/dotfiles-agents
cd ~/dotfiles-agents
./install.sh --dry-run   # see what would change
./install.sh             # personal machine
./install.sh --work      # work machine: also work skills and twg-*
```

`install.sh` is safe to re-run. It skips anything already in place and backs up any file it
replaces to `<file>.backup-<timestamp>`.

### Requirements

| Tool | Needed for | macOS | Linux (Debian/Ubuntu) |
|---|---|---|---|
| `git`, `jq` | everything | `brew install jq` | `sudo apt install git jq` |
| Node.js (`npx`) | installing skills | `brew install fnm && fnm install --lts` | same, or your distro's `nodejs` |
| `dot` (optional) | linking files | `cargo install dot_rust` | `cargo install dot_rust` |
| `claude` | plugins | `curl -fsSL https://claude.ai/install.sh \| bash` | same |
| `codex`, `opencode`, `twg` | their own steps | optional | optional |

A step whose tool is missing prints a warning and is skipped. Without `dot`, `install.sh`
creates the same symlinks with `ln -s`.

## Keeping machines in sync

```
 this machine                         repo                         other machine
──────────────                    ────────────                    ───────────────
 install a skill,      ./capture.sh    manifests,      git pull       ./install.sh
 change a setting   ───────────────▶  settings, files ─────────────▶  (installs, links,
                     then review +     in git                          merges)
                     git commit/push
```

1. **Change things normally** on whichever machine you're on: `npx skills add owner/repo -g`,
   `/config` in Claude Code, `claude plugin install …`, editing the Codex model, and so on.
2. **Capture**: `./capture.sh` copies those changes into the repo. It adds new skills to the
   manifests, writes the portable part of `~/.claude/settings.json` and the Codex keys, and copies
   back any linked file a tool replaced. It never commits.
3. **Review and commit**: `git diff`, then commit and push.
4. **Apply elsewhere**: `git pull && ./install.sh` (add `--work` on work machines).

More detail in [docs/sync-workflow.md](docs/sync-workflow.md).

## What's synced

| What | Repo | On the machine | How |
|---|---|---|---|
| Skills from GitHub/GitLab | `skills/personal.txt`, `skills/work.txt` | `~/.agents/skills/` (+ links in `~/.claude/skills/`) | reinstalled with the [`skills` CLI](https://github.com/vercel-labs/skills) |
| TWG skills (`twg-*`) | n/a | `~/.agents/skills/`, `~/.claude/skills/`, `~/.config/opencode/skills/` | `twg skills install`, with `--work` only |
| My own skills | `skills/own/<name>/` | `~/.agents/skills/<name>`, `~/.claude/skills/<name>` | symlinked, so edits go straight to the repo |
| Claude Code settings | `claude/settings.json` | `~/.claude/settings.json` | deep-merged with `jq`; local-only keys such as `hooks` are kept |
| Claude Code plugins + marketplaces | `enabledPlugins` / `extraKnownMarketplaces` in `claude/settings.json` | `~/.claude/plugins/` | `claude plugin marketplace add` / `claude plugin install` |
| Status line script | `claude/statusline-command.sh` | `~/.claude/statusline-command.sh` | symlink (`dot.toml`) |
| Codex model + reasoning effort | `codex/config.toml` | top-level keys of `~/.codex/config.toml` | merged key by key |
| Codex command rules | `codex/rules/default.rules` | `~/.codex/rules/default.rules` | symlink (`dot.toml`) |

### What's deliberately not synced

- **Credentials and history**: `~/.claude/.credentials.json`, `~/.codex/auth.json`, sessions,
  `history.jsonl`, `projects/`. Log in again on each machine.
- **Claude `hooks`**: currently all generated by Orca (`~/.orca/agent-hooks/`). Orca writes
  them again when it's installed. Excluded through `CLAUDE_SETTINGS_EXCLUDE`.
- **Codex `[projects.*]` trust entries**: absolute paths that only make sense on one machine.
- **Generated prompts and plugins**: `~/.codex/prompts/opsx-*.md` (from OpenSpec) and the Orca
  opencode plugin. The tools that made them recreate them.
- **Claude auto-memory** (`~/.claude/projects/<path>/memory`): folder names come from absolute
  paths, so they don't carry over between machines.

See [docs/other-agents.md](docs/other-agents.md) for how to recreate these.

## Commands

```
./install.sh [--work] [--update] [--only <steps>] [--dry-run]
    steps: links, skills, own, claude, plugins, codex   (default: all)
    --work     also install skills/work.txt and twg-* skills
    --update   also update installed skills to their latest version

./capture.sh [--dry-run]
```

Examples:

```sh
./install.sh --only skills,own          # just skills
./install.sh --only claude,plugins      # just Claude Code
./install.sh --update                   # refresh every skill from upstream
SKILL_AGENTS="claude-code cursor" ./install.sh --only skills
```

| Variable | Default | Meaning |
|---|---|---|
| `SKILL_AGENTS` | `claude-code opencode` | Agents the skills CLI installs for. Codex, opencode and other "universal" agents read `~/.agents/skills` directly |
| `SKILLS_CLI` | `skills@1.7.0` | npx package used for the skills CLI |
| `CLAUDE_SETTINGS_EXCLUDE` | `hooks` | Space-separated settings keys that `capture.sh` leaves out |
| `WORK_SOURCES` | `geniussports` | Regex. `capture.sh` files skills whose source matches it under `work.txt` |

## Layout

```
dotfiles-agents/
├── install.sh              repo → machine
├── capture.sh              machine → repo
├── lib/common.sh           shared helpers (paths, dot.toml / manifest / TOML parsing)
├── dot.toml                hand-written files symlinked into $HOME
├── skills/
│   ├── personal.txt        skills for every machine
│   ├── work.txt            skills for work machines (--work)
│   └── own/                skills I write myself, one folder per skill
├── claude/
│   ├── settings.json       portable part of ~/.claude/settings.json (incl. plugins)
│   └── statusline-command.sh
├── codex/
│   ├── config.toml         top-level keys merged into ~/.codex/config.toml
│   └── rules/default.rules
└── docs/
    ├── skills.md           adding, removing, updating and writing skills
    ├── claude-code.md      settings merge, plugins, status line, CLAUDE.md
    ├── other-agents.md     Codex, opencode, Cursor, Orca, OpenSpec
    └── sync-workflow.md    day-to-day sync, new machines, troubleshooting
```

## Using it from `dotfiles-macos`

To run it as part of the Mac bootstrap, add this to the end of `~/dotfiles/bootstrap.sh`, after
Node and Claude Code are installed:

```sh
AGENTS_DIR="$HOME/dotfiles-agents"
[ -d "$AGENTS_DIR" ] || git clone git@github.com:VillegasMich/dotfiles-agents.git "$AGENTS_DIR"
"$AGENTS_DIR/install.sh"
```

On Linux, clone this repo and run `install.sh` directly.
