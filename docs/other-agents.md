# Codex, opencode and other tools

## Codex

| What | Synced? | How |
|---|---|---|
| `model`, `model_reasoning_effort` | yes | `codex/config.toml`. `install.sh` sets these top-level keys in `~/.codex/config.toml`; `capture.sh` reads them back |
| `rules/default.rules` (approved command prefixes) | yes | symlinked through `dot.toml` |
| `[projects."<path>"]` trust entries | no | absolute paths specific to one machine |
| Skills | yes | Codex reads `~/.agents/skills` directly (see [skills.md](skills.md)) |
| `prompts/opsx-*.md` | no | generated by OpenSpec, see below |
| `auth.json`, sessions, sqlite state | no | log in with `codex login` |

Only the keys already listed in `codex/config.toml` are synced, so writing the merge with a small
`awk` function is enough and no TOML library is needed. To sync another top-level key, add it to
`codex/config.toml` by hand, for example `approval_policy = "on-request"`. From then on
`capture.sh` keeps it up to date. Tables (`[section]`) aren't supported. If you need them, link
the whole file with `dot.toml` instead and drop the trust entries.

If Codex replaces the `default.rules` symlink with a regular file when it saves a new rule,
`capture.sh` copies the file back into the repo, and the next `install.sh` links it again.

## opencode

opencode reads skills from `~/.agents/skills`, so it needs nothing extra. The TWG CLI also copies
its skills into `~/.config/opencode/skills` (`--agent opencode`).

Not synced: `~/.config/opencode/plugins/orca-opencode-status*`, which Orca installs.

## Cursor

`cursor-agent` is installed by `dotfiles-macos`. To give it the skills too, add it to
`SKILL_AGENTS` (see [skills.md](skills.md#which-agents-get-links)).

## Orca

Orca writes its own integration into each agent:

- the `hooks` block in `~/.claude/settings.json`, pointing to `~/.orca/agent-hooks/claude-hook.sh`
- `~/.codex/hooks.json`
- the opencode status plugin

All of these come back when Orca is installed and opened on a new machine, so none are synced.
The `orchestration` skill from `stablyai/orca` *is* synced through `skills/personal.txt`.

## OpenSpec

The `opsx-*` Codex prompts come from the OpenSpec CLI (`npm i -g @fission-ai/openspec`, already
in `dotfiles-macos`). To recreate them on a new machine, run `openspec init` in a project, or
`openspec update` to refresh existing ones.
